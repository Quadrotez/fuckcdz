# FuckCDZ

Кросс-браузерное расширение для **Chromium** и браузеров на базе **Gecko**. Расширение локально сканирует открытую страницу дневника МЭШ на `school.mos.ru` или `dnevnik.mos.ru`, собирает прикреплённые ЦДЗ и показывает их в едином интерфейсе. Тестовые материалы открываются на `uchebnik.mos.ru` в оригинальном интерфейсе, а начатую попытку можно открыть в локальном просмотрщике всех заданий.

Расширение не получает и не хранит пароль или API-токен МЭШ и не отправляет задания на внешний сервер. Snapshot теста, локальные ответы и debug-логи хранятся только в локальном хранилище браузера.

## Возможности

Расширение собирает только прикреплённые задания и сортирует их по дате, открывает тест целиком после начала попытки, отображает основные типы заданий в интерактивном виде, позволяет отправлять поддерживаемые ответы, экспортировать тест в JSON, импортировать ответы из JSON или вставкой текста, а также генерировать промпт для нейросети. Вложения в экспорт не встраиваются: сохраняются их исходные URL.

## Сборка

Требуется Python 3.9 или новее. Node.js не требуется.

Linux/macOS:

```bash
chmod +x scripts/build-extension.sh
./scripts/build-extension.sh
```

Windows:

```bat
scripts\build-extension.bat
```

Скрипт создаёт две сборки:

```text
dist/chromium/
dist/gecko/
dist/fuckcdz-chromium.zip
dist/fuckcdz-gecko.zip
```

Сборка Chromium использует Manifest V3. Сборка Gecko использует совместимый Manifest V2 с классическим background script.

## Установка

### Chromium

Необходимо открыть страницу `chrome://extensions` или совместимый раздел управления расширениями, включить **режим разработчика**, нажать **«Загрузить распакованное расширение»** и выбрать каталог `dist/chromium/`.

### Gecko

Необходимо открыть страницу временной отладки дополнений браузера, выбрать **«Загрузить временное дополнение»** и указать файл `dist/gecko/manifest.json`. Для постоянной установки следует использовать стандартный для конкретного дистрибутива способ установки подписанного дополнения.

После установки необходимо открыть страницу домашних заданий в дневнике МЭШ и запустить сбор заданий из popup расширения. Тестовые материалы открываются по исходным launch-ссылкам на `uchebnik.mos.ru`.

## Просмотр и решение теста

После начала попытки на странице теста расширение перехватывает snapshot ответа `start-attempt`. Кнопка **«Показать все задания»** открывает локальную страницу расширения, где отображаются условие, медиа, варианты ответа и тип каждого задания. Служебные поля правильных ответов и пользовательских ответов удаляются из экспортируемых данных.

Для интерактивного режима поддерживаются одиночный и множественный выбор, свободный текст, число, порядок, сопоставление, группы, таблицы и текстовые пропуски. Для каждого задания доступна отдельная кнопка отправки, если формат запроса уже поддержан текущей версией расширения. Официальное завершение попытки выполняется отдельной кнопкой после отправки ответов.

## Экспорт и импорт ответов

На странице **«Все задания теста»** доступны **«Экспорт JSON»**, **«Импорт ответов»** и импорт вставкой текста. Формат экспорта — `mesh-tasks/test-export`, версия `1`:

```json
{
  "schema": "mesh-tasks/test-export",
  "version": 1,
  "source": {
    "attempt_id": 362872773
  },
  "answers": {
    "802478499": "u9u20i",
    "802478504": "текстовый ответ"
  }
}
```

Для `answer/single`, `answer/multiple` и `answer/order` импорт принимает как ID вариантов, так и их полный текст и пытается автоматически сопоставить текст с реальным ID МЭШ. Для текстовых, числовых и gap/input-ответов используется значение соответствующего типа. После импорта расширение показывает количество применённых ответов и диагностирует неизвестные ID или неподходящие значения.

Импорт только заполняет и сохраняет локальные поля. Отправка в МЭШ выполняется отдельно кнопкой **«Отправить ответ»**.

## Генерация промпта

Кнопка **«Сгенерировать промпт»** формирует текст с JSON теста и строгим шаблоном результата. Нейросеть должна вернуть только JSON с объектом `answers`, сохранив точные ID заданий. Полученный JSON можно вставить через функцию импорта ответов.

## Debug-mode

Debug-mode предназначен для исследования сетевого поведения тестовой системы. Он наблюдает `fetch` и XHR, фиксирует URL, метод, статус, тип ответа, длительность и обезличенное содержимое JSON. Отдельно поддерживается чтение JSON внутри Blob-тела запроса отправки ответа.

Debug-лог хранится только в локальном хранилище браузера. Перехватчик маскирует поля и заголовки с названиями `authorization`, `cookie`, `token`, `password`, `jwt`, `csrf`, `session`, `secret` и похожими. Перед передачей лога третьим лицам рекомендуется вручную проверить JSON и удалить cookies, Bearer-токены, access/refresh tokens и персональные данные.

Debug-mode не изменяет запросы, не отправляет ответы на внешний сервер и не пытается автоматически решать тест.

## Ограничения

Сканер использует эвристики DOM дневника. Cross-origin iframe и содержимое тестового плеера не сканируются. Работа зависит от текущей структуры API и интерфейса МЭШ; при её изменении отдельные типы заданий могут потребовать обновления renderer-а или submitter-а.
