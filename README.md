# МЭШ: все задания

Кросс-браузерное расширение для Chromium и Firefox/LibreWolf. Расширение локально сканирует открытую страницу дневника МЭШ на `school.mos.ru`, собирает найденные карточки заданий и показывает их в едином интерфейсе. Тестовые материалы открываются на `uchebnik.mos.ru` в оригинальном интерфейсе. Для Chromium используется Manifest V3, а для Firefox/LibreWolf сборщик создаёт Manifest V2 с `background.scripts`, что совместимо с конфигурациями LibreWolf, где MV3 service worker отключён.

Расширение не получает и не хранит пароль или API-токен МЭШ и не отправляет задания на внешний сервер. Тесты открываются в оригинальном интерфейсе МЭШ.

## Сборка

Требуется Python 3.9+; Node.js не нужен.

Linux/macOS:

```bash
chmod +x scripts/build-extension.sh
./scripts/build-extension.sh
```

Windows:

```bat
scripts\build-extension.bat
```

Результаты:

```text
dist/chrome/
dist/firefox/
dist/mesh-tasks-chrome.zip
dist/mesh-tasks-firefox.zip
```

## Установка в LibreWolf

Открой `about:debugging#/runtime/this-firefox`, нажми **«Загрузить временное дополнение»** и выбери `dist/firefox/manifest.json`. Выбирать нужно именно Firefox-сборку, а не `dist/chrome/manifest.json`. После перезапуска LibreWolf временное дополнение может потребоваться загрузить повторно.

## Установка в Chromium

Открой `chrome://extensions`, включи **режим разработчика**, нажми **«Загрузить распакованное расширение»** и выбери каталог `dist/chrome/`.

После установки открой страницу домашних заданий в дневнике на `school.mos.ru` или `dnevnik.mos.ru` и нажми **«Собрать задания»**. `uchebnik.mos.ru` используется как домен тестирующей системы: найденные материалы открываются там по исходной launch-ссылке.

## Ограничения MVP

Сканер использует эвристики DOM дневника и не вмешивается в тестовый плеер. Cross-origin iframe и содержимое `uchebnik.mos.ru` пока не сканируются; кнопки материалов ведут в оригинальные launch-ссылки МЭШ. Для нового результата нужно снова нажать кнопку на странице дневника.


## Временный debug-mode для тестовой системы

Сборка `0.2.0` добавляет ранний диагностический перехват на `uchebnik.mos.ru`. Он устанавливается до загрузки приложения, наблюдает `fetch` и XHR, фиксирует URL, метод, статус, тип ответа, длительность и обезличенное содержимое JSON-ответа. Лог хранится только в `browser.storage.local`.

Для диагностики:

1. Пересобери расширение и заново загрузи `dist/firefox/manifest.json` в LibreWolf.
2. Полностью закрой вкладку теста и открой её заново, чтобы hook установился до загрузки приложения.
3. Не открывай DevTools: страница может блокировать работу при обнаружении отладчика.
4. Начни прохождение теста или дождись его загрузки.
5. Нажми плавающую кнопку **«Скачать debug-лог»** в правом нижнем углу страницы.
6. В открывшейся локальной странице нажми **«Скачать JSON»** и пришли полученный файл.

Перехватчик автоматически маскирует поля и заголовки с названиями `authorization`, `cookie`, `token`, `password`, `jwt`, `csrf`, `session`, `secret` и похожими. Перед отправкой всё равно проверь JSON вручную. Не присылай cookies, Bearer-токены, access/refresh tokens или персональные данные.

В текущей версии debug-mode предназначен только для исследования: он не изменяет запросы, не отправляет ответы на внешний сервер и не пытается отправлять ответы теста.


## Просмотр всех заданий текущего теста

После начала попытки на странице `uchebnik.mos.ru` расширение перехватывает ответ:

```text
POST /webtests/exam/rest/secure/challenge/{challenge_id}/start-attempt
```

В ответе МЭШ передаёт `challenge_test_groups[].challenge_tasks[]`, то есть полный набор заданий текущей попытки. Кнопка **«Показать все задания»** открывает локальную страницу расширения и отображает `question_elements`, варианты ответа и тип каждого задания. Служебные поля `right_answer` и `user_answer` намеренно не показываются.

Страница является просмотрщиком snapshot и не отправляет ответы. Оригинальный тест можно продолжать в исходной вкладке.


### Сбор данных по нескольким тестам

Один debug-лог можно использовать для нескольких тестов подряд. Не очищай журнал между тестами: каждое событие содержит URL challenge, а каждый ответ `start-attempt` содержит собственный `challenge_attempt_id`. Рекомендуемый порядок — открыть тест, начать попытку, сделать несколько действий или отправить ответы, затем открыть следующий тест. После четвёртого теста скачай один общий JSON.

В версии `0.3.0` debug-mode дополнительно читает содержимое JSON внутри Blob-тела запроса `/challenge/task/answer`. Для каждого ответа в логе появится поле `requestBody.blobType`, `requestBody.blobSize` и, если тело является JSON, `requestBody.json`. Полные секреты авторизации и чувствительные поля продолжают маскироваться.


## Экспорт теста и импорт ответов

На странице **«Все задания теста»** доступны кнопки **«Экспорт JSON»** и **«Импорт ответов»**. Экспорт не содержит cookies, Bearer-токены или ключи правильных ответов. Вложения не встраиваются в файл: сохраняются их исходные URL, поэтому JSON остаётся компактным и пригодным для обработки сторонними скриптами.

Формат файла экспорта — `mesh-tasks/test-export`, версия `1`:

```json
{
  "schema": "mesh-tasks/test-export",
  "version": 1,
  "exported_at": "2026-09-04T18:00:00.000Z",
  "source": {
    "url": "https://uchebnik.mos.ru/exam/challenge/138072708",
    "challenge_id": "138072708",
    "attempt_id": 362872773
  },
  "tasks": [
    {
      "id": 802478499,
      "order": 0,
      "type": "answer/single",
      "question_elements": [],
      "answer": {
        "options": []
      }
    }
  ],
  "answers": {
    "802478499": "u9u20i",
    "802478504": "текстовый ответ"
  }
}
```

`tasks` содержит нормализованный список заданий, включая `question_elements`, тип и варианты. Медиа остаются внутри `question_elements`: у изображения или видео используются поля `relative_url` и `preview_url`, например:

```json
{
  "atomic_type": "image",
  "description": "Иллюстрация к заданию",
  "relative_url": "https://uchebnik.mos.ru/cms/.../original/file.jpg",
  "preview_url": "https://uchebnik.mos.ru/cms/.../icon/file.jpg"
}
```

`answers` — объект с ID задания в качестве ключа. Значение должно соответствовать локальной модели интерфейса: для `answer/single` это строковый ID выбранного варианта, для `answer/multiple` массив ID, для `answer/free` и `answer/string` строка, для `answer/number` число или числовая строка, для `answer/order` массив значений порядка, а для `answer/match`, `answer/groups` и `answer/gap/match/text` объект соответствий или позиций.

Для импорта можно использовать полный экспорт или отдельный файл только с ответами:

```json
{
  "schema": "mesh-tasks/test-export",
  "version": 1,
  "source": {
    "attempt_id": 362872773
  },
  "answers": {
    "802478499": "u9u20i",
    "802478504": "текстовый ответ"
  }
}
```

Также поддерживается упрощённый объект без метаданных:

```json
{
  "802478499": "u9u20i",
  "802478504": "текстовый ответ"
}
```

При импорте расширение проверяет JSON, схему и совпадение `attempt_id`. Неизвестные ID заданий игнорируются, а ответы от другой попытки отклоняются. Импорт только заполняет и сохраняет локальные поля; отправка в МЭШ выполняется отдельно кнопкой **«Отправить ответ»**.
